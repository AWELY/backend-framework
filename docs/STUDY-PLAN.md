# خطة فهم ومراجعة المشروع (للفريق)

**الهدف:** أن يفهم كل عضو المشروع كاملاً، وأن يستطيع شرح أي جزء منه والدفاع عنه أمام لجنة المناقشة.

**المدة:** 10 جلسات، مدة كل منها ساعتان إلى ثلاث، أي أسبوعان تقريباً بجلسة يومية.

**كل جلسة فيها أربعة أجزاء:**
1. **الهدف.**
2. **ماذا تقرأ، وبأي ترتيب:** ملفات الكود وأقسام التقرير.
3. **تمرين عملي**، لأن الفهم يأتي من التجربة لا من القراءة وحدها.
4. **أسئلة تحقق:** إن لم تستطع الإجابة عنها، أعد الجلسة.

**المراجع الأساسية طوال الخطة:**
- `docs/PROJECT-MAP.md`: أين يوجد كل شيء في الكود.
- التقرير في `documents/report/Graduation_Project_Report_EN.pdf` (عندي على الجهاز، أرسله للفريق).
- `docs/API.md`: كل المسارات.

**قاعدة التمارين التي تعدّل الكود:** اعملها على فرع تجريبي ثم احذفه، حتى لا يختلط بالعمل الحقيقي:
```bash
git switch -c practice        # قبل التمرين
git switch main               # بعد التمرين
git branch -D practice        # حذف الفرع التجريبي
git checkout -- .             # إن عدّلت شيئاً على main بالخطأ
```

## الجلسة 0: التجهيز (مرة واحدة، قبل البداية)

**الهدف:** المشروع يعمل على جهاز كل عضو.

- Windows: اتبع `docs/SETUP.md`. Linux: اتبع `docs/SETUP-LINUX.md`.
- في النهاية يجب أن يظهر `ALL CHECKS PASSED` بعد:
  ```bash
  npm run verify
  ```
- ثبّت أداة لإرسال الطلبات يدوياً: **Postman**، أو إضافة **Thunder Client** في VS Code.
- شغّل متجر AMA (`storefront/README.md`) وافتح http://localhost:5173.

**تحقق:** كل عضو فتح المتجر على جهازه، واشترى منتجاً، وتتبّع طلبه.

## الجلسة 1: الصورة الكاملة

**الهدف:** أن تشرح المشروع كله في 3 دقائق: ما المشكلة، وما الحل، وكيف يتركب.

**اقرأ:**
1. المقترح: `documents/proposal/E-Commerce_Project_Proposal_EN_v4.docx`.
2. التقرير، الفصل 1 كاملاً والفصل 2 (خاصة 2.1 و2.7).
3. `README.md` ثم `docs/PROJECT-MAP.md`.
4. التقرير: شكل 4.1 (المعمارية) وشكل 4.2 (الطبقات).

**تمرين:**
- شغّل المتجر، وافتح أدوات المطوّر في المتصفح (F12) ثم تبويب **Network**.
- اشترِ منتجاً وراقب الطلبات التي يرسلها الموقع إلى المنفذ 3000.
- اكتب قائمة بالمسارات التي رأيتها بالترتيب (مثل `POST /carts` ثم `POST /carts/:id/items` ...).
- **هذا هو معنى Headless:** الموقع مجرد عميل يستهلك الـ API.

**أسئلة تحقق:**
- ما الفرق بين Monolithic وHeadless؟ ولماذا اخترنا Headless؟
- لماذا "خفيف الوزن"؟ اذكر 3 أدلة بالأرقام من التقرير (جدول 6.8).
- ما الذي يوجد خارج نطاق المشروع؟ ولماذا؟
- لماذا منهجية الشلال (Waterfall) وليس Agile؟ (التقرير 1.6 و2.6)

**تمرين:**

   ```js
   app.router.get("/hello/:name", (req, res) => res.json({ hello: req.params.name }));
   ```

**أسئلة تحقق:**

## الجلسة 4: قاعدة البيانات

**الهدف:** أن تشرح تصميم الجداول، وكيف يُنشأ المخطط، ولماذا نحتاج المعاملات.

**اقرأ:**
1. التقرير: 4.6 كاملاً (شكل 4.9 ER بنمط Chen، وشكل 4.10 الجداول، وجدول 4.2).
2. `src/db/connection.ts`، ثم `repository.ts`، ثم `errors.ts`.
3. `src/db/migrations.ts`: لاحظ الـ advisory lock.
4. `src/db/transaction.ts`.
5. ملفات `*.schema.ts` في كل وحدة. هنا تعريف الجداول (SQL).
6. `src/modules/products/products.repository.ts`: مثال Repository كامل.

**تمرين:**
- ادخل قاعدة المتجر بـ psql، ونفّذ:
  ```sql
  \dt
  \d orders
  SELECT * FROM schema_migrations;
  SELECT name, price FROM products ORDER BY price DESC LIMIT 5;
  SELECT o.id, o.total, i.product_name, i.unit_price FROM orders o JOIN order_items i ON i.order_id = o.id LIMIT 5;
  ```
- جرّب أن تكسر قيداً بنفسك: `UPDATE inventory SET quantity = -1;` لماذا ترفضه القاعدة؟

**أسئلة تحقق:**
- لماذا نحفظ الاسم والسعر داخل `order_items` مع أن المنتج موجود في `products`؟ (ليس تكراراً، بل تاريخ)
- لماذا المبالغ أرقام صحيحة (دراهم) وليست كسوراً؟
- لماذا UUID وليس أرقاماً متسلسلة؟
- ما فائدة `UNIQUE` على `orders.cart_id`؟
- لماذا لا نستخدم ORM؟ وكيف نمنع SQL Injection بدونه؟

## الجلسة 5: الأمان

**الهدف:** أن تشرح كل آلية حماية: ماذا تمنع، وأين في الكود، وأي اختبار يثبتها (جدول 6.6).

**اقرأ:**

2. `src/middleware/auth.ts` ثم `src/engine/access-control.ts`.
3. `src/engine/password.ts` (scrypt) ثم `src/engine/auth-token.ts` (HMAC).
4. `src/engine/rate-limiter.ts` و`src/engine/http/client-ip.ts`.
5. `src/modules/customers/index.ts`: مسارا التسجيل والدخول.

7. الاختبارات: `tests/unit/auth-crypto.test.ts` و`tests/integration/login-rate-limit.test.ts`.

**تمرين:**
- سجّل دخولاً بكلمة مرور خاطئة 11 مرة متتالية. ما الرد في المرة الحادية عشرة؟ ما قيمة `Retry-After`؟ (ثم أعد تشغيل الخادم لتصفير العدّاد)

  ```bash
  node -e "console.log(Buffer.from(process.argv[1].split('.')[0],'base64url').toString())" <TOKEN>
  ```
  ما الموجود فيه؟ لماذا لا يستطيع أحد تعديله؟ جرّب تغيير حرف في الجزء الأول وأرسله: ماذا يحدث؟

**أسئلة تحقق:**
- لماذا نعطي نفس رسالة الخطأ للبريد غير الموجود ولكلمة المرور الخاطئة؟ وما فائدة `verifyAgainstDummy`؟
- لماذا يُفحص حد المحاولات **قبل** التحقق من كلمة المرور؟ (جدول 6.10: من 528ms إلى 4ms)
- ما الفرق بين المصادقة (Authentication) والتفويض (Authorization) في كودنا؟
- ما قيود الأمان المعروفة؟ (التقرير 7.3) كن صريحاً بها في المناقشة، فهذا يُحسب لكم لا عليكم.
