# متجر AMA — إلكترونيات وإكسسوارات الهواتف

متجر إلكتروني تجريبي في **طرابلس - تاجوراء**، مبني فوق الإطار. هو التطبيق العملي الذي ينص عليه المقترح: ربط الإطار بمتجر حقيقي.

```
storefront/
├─ api/            خادم المتجر: يستخدم الإطار كمكتبة
│  ├─ app.js       كل إعدادات المتجر (المدن وأسعار التوصيل، الدفع عند الاستلام، الاستلام من المحل)
│  └─ seed.js      كتالوج المنتجات التجريبي
├─ web/            الموقع: HTML + CSS + JavaScript بلا أي مكتبة
│  ├─ index.html   الرئيسية والأقسام والبحث
│  ├─ product.html صفحة المنتج
│  ├─ cart.html    السلة
│  ├─ checkout.html إتمام الطلب (المدينة، التوصيل، الدفع)
│  ├─ account.html الدخول والتسجيل
│  ├─ orders.html  طلباتي
│  ├─ track.html   تتبّع الطلب برقمه ورقم الهاتف (للضيف)
│  └─ js/config.js اسم المتجر، العنوان، رقم واتساب
├─ web-server.js   خادم صغير يعرض الموقع (بلا مكتبات)
├─ start.js        يشغّل الخادمين معاً
└─ tests/browser.mjs  اختبار في متصفح حقيقي
```

**Headless:** الموقع والـ API **خادمان منفصلان**. يحمّل المتصفح الصفحات من الأول (المنفذ 5173)، ويتصل بالثاني (المنفذ 3000) مباشرة. هذا ما يعنيه "Headless" في عنوان المشروع: يمكن استبدال الموقع بتطبيق جوال دون تغيير سطر في الإطار.

## التشغيل

المتطلبات: أن يكون الإطار مبنياً (`npm install` ثم `npm run build` في المجلد الرئيسي)، وPostgreSQL تعمل.

**1. قاعدة بيانات المتجر** (مرة واحدة)

على ويندوز:
```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -h localhost -U postgres -d postgres -c "CREATE DATABASE ama_store OWNER commerce_app;"
```

على Linux:
```bash
cd /tmp && sudo -u postgres psql -c "CREATE DATABASE ama_store OWNER commerce_app;"
sudo -u postgres psql -d ama_store -c "ALTER SCHEMA public OWNER TO commerce_app;"
```

**2. الإعداد** (مرة واحدة، داخل مجلد `storefront`)

```bash
cd storefront
npm install
npm run setup -- --db-password كلمة_مرور_commerce_app
npm run migrate
npm run seed
```

**3. التشغيل**

```bash
npm start
```

ثم افتح **http://localhost:5173** في المتصفح. للإيقاف: `Ctrl + C`.

## إدارة المتجر (صاحب المتجر)

لا توجد لوحة تحكم منفصلة (خارج نطاق المقترح). يدير صاحب المتجر المنتجات والطلبات **عبر الـ API مباشرة**، من Postman أو curl، بإرسال الترويسة `X-Api-Key` بقيمة `OWNER_API_KEY` من ملف `storefront/.env`. مثال لتأكيد طلب:

```bash
curl -X PATCH http://localhost:3000/orders/<رقم الطلب>/status \
  -H "X-Api-Key: <OWNER_API_KEY>" -H "Content-Type: application/json" \
  -d '{"status":"confirmed"}'
```

كل المسارات في `../docs/API.md`.

## التخصيص

| ماذا | أين |
|---|---|
| المدن وأسعار التوصيل، والتوصيل المجاني فوق 500 د.ل | `api/app.js` (`DELIVERY_RATES`) |
| رسالة الدفع عند الاستلام، والاستلام من المحل | `api/app.js` |
| اسم المتجر، العنوان، **رقم واتساب** (يظهر زر عائم عند وضعه) | `web/js/config.js` |
| الألوان والخطوط | `web/css/styles.css` (المتغيرات في أوله) |
| صور المنتجات | ضع الصور في `web/images/products/` واجعل `imageUrl` للمنتج يشير إليها |

## الأمان في الموقع

- **منع حقن الكود:** كل نص يأتي من الـ API يُهرَّب قبل عرضه، فاسم منتج فيه كود لا يُنفَّذ.
- **سياسة أمان المحتوى (CSP):** المتصفح لا يشغّل إلا سكربتات الموقع نفسه، ولا يتصل إلا بـ API المتجر.
- **الوصول للملفات:** خادم الموقع لا يسمح بالوصول لأي ملف خارج مجلد `web` (مثل `.env`).
- **CORS:** الـ API يقبل الطلبات من عنوان الموقع فقط (`CORS_ORIGIN`).

## الاختبار

- **ضمن الفحص الشامل:** `npm run verify` في المجلد الرئيسي يفحص المتجر أيضاً: الصفحات، وسياسة الأمان، ومدن التوصيل، وCORS.
- **اختبار في متصفح حقيقي:** شغّل المتجر (`npm start`) ثم في نافذة أخرى:
  ```bash
  npm run test:browser
  ```
  - **ماذا يفعل:** يفتح Edge أو Chrome أو Chromium بلا واجهة، ويمر برحلة زبون كاملة: تصفح، وبحث، وسلة، وإتمام طلب، وتتبّع، وتسجيل، و"طلباتي".
  - **ماذا يفحص:** أي خطأ JavaScript أو مخالفة لسياسة الأمان.
  - **الصور:** يلتقط صورة لكل صفحة في `tests/screenshots/`.
  - **تنبيه:** ينشئ طلبات وحسابات حقيقية، فشغّله على قاعدة تجريبية فقط. لإعادة المتجر نظيفاً: امسح القاعدة ثم `npm run migrate` و`npm run seed`.
